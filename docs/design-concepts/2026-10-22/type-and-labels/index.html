Type and labels: alternatives

Five choices from the Hallmark audit that are yours to make: the small uppercase labels, the face that sets them, the greys, the interface face and the heading weight. Each decision shows the site as PR #204 leaves it (option A), then two or three alternatives drawn in HTML with the site’s real type sizes, colors and copy, on real page fragments: the /work first screen, the About Audio chapter, closing bands, the /services doors and captions.

Option A uses the CI captures of PR #204 at f0abd1f, which include the audit fixes. Where the alternatives need a line-for-line comparison (the /work first screen, the /services doors, the Lyft figure and the contact field), option A is drawn in HTML from PR #204’s CSS like them, and the frame says so. A drawn line can break one word sooner or later than in a CI capture, because CI renders with another browser build. Nothing here is built. None of these options adds motion, and every picture is an existing site picture or a CI capture, so nothing needs image QA. Pick one option per decision; the recommended one is marked.

D4.1 · Kickers

Which small uppercase labels above headings should stay?

Hallmark flagged a kicker above nearly every heading, on nine page groups (punch list #8). A label that repeats the nav, the page title or the heading under it reads as template habit, and it dilutes the labels that carry facts.

Where it was decided. The selected studies draw page and closing-band labels (docs/design-concepts/2026-09-09/work-v1.png and about-personal-path-v1.png, listed in docs/design-concepts/README.md:8). The brief board draws form kickers (docs/design-concepts/2026-10-19/website-intake/index.html:472-477), and Building puts a status on every row (docs/audits/2026-09-26/website-simplification-audit.md:342-345). Tally’s “Three highlights from the journal” and “Decision” labels have no design record. In the studies the closing-band labels added something: the Work study put “Let’s talk” over “An interesting problem or possibility?”, and the About study put “Let’s connect” over “Let’s find a connection.”. The shipped About heading is now “Let’s talk.”, so its label no longer adds anything.

D4.2 · Label face

Which typeface should set the small labels?

Hallmark wants an outlier face like JetBrains Mono in two places at most (gate 38, punch list #10). Here mono sets the kickers, the project status lines, Tally’s step labels, the Work diagram phase labels, the Threadline step numbers, and Home’s capacity key and code field.

Where it was decided. docs/website-system-plan.md:26-28 keeps “the existing monospace role”, and the September 26 audit asked for one kicker face (docs/audits/2026-09-26/website-simplification-audit.md:470,477-479). Both selected studies draw the labels in small mono capitals in the accent: “WORK”, “LYFT · BULK BONUS REFACTOR” and “LET’S TALK” in work-v1.png, “ABOUT”, “AUDIO” and “LET’S CONNECT” in about-personal-path-v1.png. PR #204 already sets every kicker in that one mono face. The audit’s verifier rated Hallmark’s “major” as overstated. Every option keeps mono for real code and data: Home’s code field and its capacity key.
